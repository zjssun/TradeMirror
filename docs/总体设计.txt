  技术说明

  1. 桌面端：Tauri

  Tauri 负责桌面应用外壳，而非业务分析逻辑。

  主要职责：

  - 启动和关闭 Python 分析引擎。
  - 分配引擎使用的随机本地端口。
  - 生成一次性访问令牌，避免其他本地程序直接调用引擎接口。
  - 管理应用数据目录、日志目录、导出目录。
  - 提供文件选择、保存文件、窗口控制等原生能力。
  - 打包 React 前端、Python Engine 和运行所需 DLL。

  推荐运行流程：

  用户打开 TradeMirror.exe
          ↓
  Tauri 创建本地工作目录
          ↓
  Tauri 启动 PyInstaller 打包后的 Python Engine
          ↓
  Engine 启动 FastAPI，监听 127.0.0.1 随机端口
          ↓
  Tauri 检查 /health 接口
          ↓
  React UI 加载并连接 Engine
          ↓
  用户开始导入、分析和导出

  Python 引擎必须仅监听：

  127.0.0.1

  不应监听 0.0.0.0，避免局域网中的其他设备访问交易数据。

  4. MT5 集成设计

  MetaTrader5 Python API 依赖用户本机已经安装并运行的 MT5 Terminal。

  连接策略

  1. 启动时尝试 mt5.initialize()。
  2. 未检测到 MT5 时，前端显示“未连接”，但仍允许 CSV 导入和历史数据管理。
  3. 用户启动 MT5 后可手动重试连接。
  4. 连接成功后读取：
    - 终端版本；
    - 账户登录号；
    - 经纪商服务器；
    - 账户货币；
    - 已选中及可见 Symbol 列表。

  市场数据策略

  - 默认获取 OHLCV K线，不默认存储 Tick。
  - 支持用户选择时间周期，例如 M1、M5、M15、H1、H4、D1。
  - 对已读取的历史数据做 SQLite 缓存。
  - 同一 Symbol、周期、时间范围优先使用缓存，缺失区间再请求 MT5。
  - Tick 数据仅用于未来需要精细计算滑点、持仓内极值时按需加载，避免数据库膨胀。

  5. CSV 订单导入设计

  不同经纪商 CSV 列名和格式不统一，因此导入必须分为两步。

  第一步：自动识别

  自动识别常见别名，例如：

  ┌─────────────┬───────────────────────────────────────┐
  │  标准字段   │           可能识别的CSV列名           │
  ├─────────────┼───────────────────────────────────────┤
  │ ticket      │ Ticket、Order、Deal、订单号、交易编号 │
  ├─────────────┼───────────────────────────────────────┤
  │ symbol      │ Symbol、Instrument、品种、交易品种    │
  ├─────────────┼───────────────────────────────────────┤
  │ direction   │ Type、Side、Direction、买卖、方向     │
  ├─────────────┼───────────────────────────────────────┤
  │ open_time   │ Open Time、Time、开仓时间             │
  ├─────────────┼───────────────────────────────────────┤
  │ close_time  │ Close Time、平仓时间                  │
  ├─────────────┼───────────────────────────────────────┤
  │ open_price  │ Open Price、Price Open、开仓价        │
  ├─────────────┼───────────────────────────────────────┤
  │ close_price │ Close Price、Price Close、平仓价      │
  ├─────────────┼───────────────────────────────────────┤
  │ volume      │ Volume、Lots、Size、手数              │
  ├─────────────┼───────────────────────────────────────┤
  │ profit      │ Profit、P/L、Net Profit、盈亏         │
  ├─────────────┼───────────────────────────────────────┤
  │ commission  │ Commission、手续费                    │
  ├─────────────┼───────────────────────────────────────┤
  │ swap        │ Swap、隔夜利息                        │
  └─────────────┴───────────────────────────────────────┘

  第二步：用户确认映射

  如果识别置信度不足，前端必须要求用户确认字段映射。

  导入前校验：

  - 必填字段是否完整；
  - 开仓时间是否早于平仓时间；
  - 买卖方向是否合法；
  - 交易量、价格、利润是否可解析；
  - 重复 ticket 是否已存在；
  - 时间格式和时区是否可识别。

  导入后保留原始 CSV 文件元数据和字段映射配置，方便同一经纪商下一次自动复用。

  6. 交易分析引擎设计

  每笔交易生成一个 TradeContext。

  K线窗口

  默认以交易周期对应的 K线为基础：

  开仓前：30根K线
  持仓期间：完整K线区间
  平仓后：20根K线

  该参数应支持在设置中调整。

  分析内容

  TradeContext
  ├── trade
  │   ├── ticket
  │   ├── symbol
  │   ├── direction
  │   ├── open_time
  │   ├── close_time
  │   ├── open_price
  │   ├── close_price
  │   ├── volume
  │   └── realized_profit
  │
  ├── market_context
  │   ├── timeframe
  │   ├── trend
  │   ├── volatility
  │   ├── atr
  │   ├── rsi
  │   ├── ema_20
  │   ├── ema_50
  │   ├── support_levels
  │   ├── resistance_levels
  │   └── candle_snapshot
  │
  ├── trade_execution
  │   ├── holding_duration
  │   ├── maximum_favorable_excursion
  │   ├── maximum_adverse_excursion
  │   ├── max_drawdown
  │   ├── max_profit_during_trade
  │   ├── entry_position_score
  │   ├── exit_position_score
  │   └── risk_reward_estimate
  │
  └── result
      ├── gross_profit
      ├── commission
      ├── swap
      ├── net_profit
      └── result_category

  指标计算原则

  - 所有指标仅使用交易发生前或交易持有期间已经存在的历史数据。
  - 不使用交易结束后的市场数据评价入场信号。
  - 平仓后的 K线只用于复盘出场后的市场演变，不可用于伪造当时可获得的信息。
  - 明确区分“事前可见信息”和“事后复盘信息”。

  这是避免“未来函数”和错误归因的关键。

  7. Trader Profile 生成设计

  交易者画像为规则统计与可解释标签组合，不应伪装成预测模型。

  可计算维度

  交易风格
  ├── 持仓时间分布
  ├── 常用周期
  ├── 常用品种
  ├── 趋势方向交易比例
  └── 顺势 / 逆势交易比例

  风险偏好
  ├── 单笔风险分布
  ├── 最大连续亏损
  ├── 盈亏比
  ├── 胜率
  ├── 最大回撤
  └── 加仓 / 摊平行为

  执行习惯
  ├── 提前平仓比例
  ├── 亏损单持仓时间
  ├── 盈利单持仓时间
  ├── 高频交易倾向
  ├── 交易时段分布
  └── 连续亏损后交易行为

  优势识别
  ├── 表现最佳品种
  ├── 表现最佳时段
  ├── 表现最佳方向
  ├── 高胜率条件
  └── 高盈亏比条件

  8. TMF 文件格式设计

  .tmf 是标准 ZIP 容器，扩展名改为 .tmf。

  推荐目录结构

  TradeMirror_20260731.tmf
  ├── manifest.json
  ├── trades.json
  ├── market_context.json
  ├── trader_profile.json
  ├── ai_prompt.txt
  ├── metadata/
  │   ├── source_summary.json
  │   └── field_mapping.json
  ├── charts/
  │   ├── trade_000001.png
  │   └── trade_000002.png
  └── README.txt

  manifest.json

  {
    "format": "TradeMirror Memory File",
    "format_version": "1.0.0",
    "generated_at": "2026-07-31T10:30:00Z",
    "application_version": "0.1.0",
    "trade_count": 120,

  隐私设计

  导出时提供可选脱敏：

  - 账户登录号脱敏；
  - 经纪商服务器名称隐藏；
  - 订单 ticket 哈希化；
  - 交易品种可保留或匿名化；
  - 不导出账户余额、身份证明、联系方式等信息；
  - 用户可选择是否包含图表 PNG。

  TMF 中应默认不包含 MT5 登录凭据、密码、Token 或原始终端配置。

  数据库设计

  数据库使用单个 SQLite 文件，例如：

  %APPDATA%/TradeMirror/data/trademirror.db

  开发阶段可使用 Alembic 管理数据库迁移。

  trades          1 ─── N  analysis_runs
  profile_runs    N ─── 1  import_batches
  export_jobs     N ─── 1  import_batches

  ---
  开发路线

  Phase 1：项目初始化与本地通信

  目标：建立可启动、可通信的桌面应用骨架。

  交付内容：

  - Tauri + React + TypeScript + Vite 初始化。
  - Ant Design 基础主题和应用布局。
  - Python 3.12 + FastAPI 初始化。
  - Tauri 自动启动和停止 Python Engine。
  - 前端调用 GET /health。
  - 本地随机端口与访问令牌机制。
  - SQLite 初始化与基础迁移。
  - 基础日志系统。
  - Windows 开发环境启动说明。

  验收标准：

  启动 TradeMirror 后：
  1. Tauri窗口正常显示。
  2. Python Engine 被自动启动。
  3. UI显示“分析引擎已连接”。
  4. 关闭桌面应用后，Python进程自动退出。

  ---
  Phase 2：MT5 连接与市场数据

  目标：读取用户本地 MT5 Terminal 的状态、品种和 K线。

  交付内容：

  - MT5 初始化与断线重连。
  - MT5状态接口。
  - 账户信息读取。
  - Symbol 搜索、筛选、选择。
  - K线读取接口。
  - K线缓存到 SQLite。
  - 前端 MT5 状态页。
  - 前端 Symbol 选择页。
  - 基础 K线图展示。

  验收标准：

  用户启动本机MT5后：
  1. TradeMirror能够显示连接状态。
  2. 能够读取账户和Symbol列表。
  3. 用户选择任意可用Symbol。
  4. 能够读取并显示对应历史K线。

  ---
  Phase 3：订单 CSV 导入与存储

  目标：稳定导入多个经纪商格式的历史订单。

  交付内容：

  - CSV 文件选择。
  - 编码识别：UTF-8、UTF-8 BOM、GBK 等。
  - 自动字段检测。
  - 前端字段映射确认页面。
  - 标准化交易记录转换。
  - 数据校验和错误报告。
  - 导入批次管理。
  - trades 表存储。
  - 交易列表、筛选、分页和详情页面。

  验收标准：

  用户选择经纪商导出的CSV后：
  1. 软件自动识别常见字段。
  2. 无法识别时可手动映射。
  3. 数据校验异常会指出具体行与原因。
  4. 成功交易记录可在交易列表中查看。

  ---
  Phase 4：交易与行情融合分析

  目标：针对每笔历史交易生成结构化交易上下文。

  交付内容：

  - 根据交易品种与时间匹配 K线。
  - 自动补全所需 K线数据。
  - 开仓前、持仓期间、平仓后 K线窗口提取。
  - 趋势分析。
  - ATR、RSI、EMA 等基础指标。
  - 支撑阻力识别。
  - MFE、MAE、最大浮盈、最大浮亏计算。
  - TradeContext 数据生成和持久化。
  - 单笔交易复盘 API。

  验收标准：

  选择一笔交易后：
  1. 显示开仓、平仓所在K线。
  2. 显示持仓期间行情。
  3. 显示趋势、波动率和关键指标。
  4. 显示最大浮盈、最大浮亏与持仓回撤。

  ---
  Phase 5：交易者画像与 TMF 导出

  目标：将交易数据转换为可供 AI 分析的标准化文件。

  交付内容：

  - 历史交易统计。
  - Trader Profile 规则生成。
  - AI Prompt 模板生成。
  - TMF Manifest 生成。
  - 交易、上下文、画像 JSON 导出。
  - 交易图表 PNG 渲染。
  - ZIP 格式 .tmf 打包。
  - 导出范围和脱敏选项。
  - TMF 文件结构校验。

  验收标准：

  用户点击“导出TMF”后：
  1. 可选择交易范围、品种和日期。
  2. 可选择是否导出图表和脱敏信息。
  3. 成功生成 .tmf 文件。
  4. 将 .tmf 改为 .zip 后可正常解压。
  5. 内部 manifest、JSON、Prompt和图表文件完整。

  ---
  Phase 6：完整交易复盘 UI

  目标：形成可用的桌面交易复盘体验。

  交付内容：

  - Dashboard。
  - 交易统计图表。
  - TradingView 风格 K线复盘页面。
  - 买卖点、止损、止盈标记。
  - 时间轴缩放、平移和定位。
  - 单笔交易侧栏分析。
  - Trader Profile 页面。
  - AI Prompt 预览、复制和导出。
